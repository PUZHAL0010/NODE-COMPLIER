1. Executive Summary

A comprehensive architectural audit, runtime failure verification, security review, and performance test were executed across the distributed Node.js Web IDE and code execution platform. The assessment verified the complete request-to-execution pipeline from frontend user interaction, Monaco editor synchronization, API Gateway schema validation, rate limiting, BullMQ queue dispatch, isolated sandbox execution, real-time SSE streaming, to sandboxed HTML/CSS/JS preview rendering.

2. Current Architecture

The platform follows a decoupled, security-first distributed architecture with four main layers:

  • Stateless API Gateway (Express 4): Handles request validation (Zod), rate limiting (10 req/min), CORS, and Server-Sent Events (SSE) live streaming.
  • Queue & Orchestration (BullMQ + Redis 7): Enqueues jobs, manages concurrency, and balances execution across worker instances.
  • Execution Processor & In-Memory Compiler: Compiles TypeScript in memory, checks AST rules, and dispatches jobs to isolated sandboxes.
  • Sandbox Runtime (Docker & Process): Executes user code under strict cgroup limits (512MB RAM, 1.0 CPU, 32 PIDs, read-only FS, network isolation).

4. Immediate Failures & Root Cause Resolution

Failure Investigated: Error: spawn taskkill ENOENT during process timeout cleanup on Windows.

Root Cause: spawn('taskkill') failed when SystemRoot\System32 was not explicitly in PATH, and the spawned ChildProcess lacked an unhandled error listener.

Resolution Applied: Implemented a robust cross-platform process tree killer in server/sandbox/ProcessSandboxRuntime.ts using absolute taskkill.exe path with fallback signal termination and POSIX process-group SIGKILL.

7. Module System Tests

Tested CommonJS (require / module.exports) and ES Modules (import / export), relative module resolution (./utils.js), JSON imports (config.json), and package resolution for express, mysql2, axios, lodash, uuid, and dayjs. All resolved seamlessly (PASS).

8. TypeScript Tests

  • Valid TypeScript: Interfaces, generics, and types compiled to ES2022 and executed (PASS).
  • Compilation Diagnostics: Invalid types (e.g. const x: number = "abc") produced structured COMPILATION_ERROR with exact file, line, column, and diagnostic message (PASS).

9. Filesystem Tests

All operations are strictly contained inside /tmp/ide-sandboxes/sandbox-<id>. Path traversal attempts with ../, ..\, null bytes (\0), absolute paths (/etc/passwd), and Windows device names (CON.js, NUL.txt) were rejected by fileValidation.ts with FileValidationError (PASS).

10. Process Tests

User code executes with sanitized process.env. When child processes are spawned, timeout cleanup reaps all child processes and process trees without leaving zombie processes (PASS).

11. Network Tests

Local dev mode allows outgoing HTTP REST requests (fetch() / axios). In strict production Docker mode, --network none blocks external network access at the Linux kernel level (PASS).

12. Security Tests

  • Buffer Safety: Replaced unbounded buffers with BoundedOutputCollector (1 MB cap).
  • Environment Scrubbing: Infrastructure credentials (Redis, database passwords, cloud tokens) are not passed to user sandboxes.
  • AST Analyzer: Checks for dangerous internal process bindings and prototype pollution.

13. Sandbox Tests

Container configuration enforces non-root execution, dropped Linux capabilities (--cap-drop ALL), read-only root FS (--read-only), 512MB RAM cap, and 32 max PIDs (PASS).

14. HTML Preview Tests

Multi-file HTML projects inline CSS stylesheets and JS scripts into a single sandbox bundle protected by a strict Content Security Policy (connect-src 'none'; default-src 'none') (PASS).

15. Multi-Page Preview Tests

Built a Virtual Client Router into PreviewService allowing multi-page HTML projects (index.html, about.html, contact.html) to navigate relative links safely without leaving the iframe (PASS).

16. Frontend Tests

Added automatic localStorage synchronization in public/app.js so user-created files, tabs, and code modifications persist across browser page refreshes (PASS).

17. API Tests

Verified POST /api/v1/jobs (202 Accepted), GET /api/v1/jobs/:id/stream (SSE live output), POST /api/v1/jobs/:id/cancel (200 OK), GET /healthz (200 OK), and GET /readyz (200 OK) (PASS).

18. Redis Tests

Verified Redis connection and reconnection handling. Production Compose uses redis:7-alpine for 100% BullMQ v5 compatibility (PASS).

19. BullMQ Tests

Verified queue job insertion, worker pickup, job completion, and failure handling without retry loops on deterministic user errors (PASS).

20. Worker Tests

Worker pool scales concurrently with 8 parallel worker threads (configurable via WORKER_CONCURRENCY) (PASS).

21. Timeout Tests

Infinite loops (while(true){}) trigger a hard timeout at 5000ms, kill the process tree, and leave the worker healthy for subsequent jobs (PASS).

22. Cancellation Tests

Long-running executions are terminated immediately upon user stop request (POST /api/v1/jobs/:id/cancel), releasing active job concurrency counters (PASS).

23. Resource Limit Tests

V8 heap is capped at 512MB (--max-old-space-size=512) and stdout is clamped at 1MB, preventing host out-of-memory crashes (PASS).
